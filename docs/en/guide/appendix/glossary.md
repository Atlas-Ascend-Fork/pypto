# Glossary

| Term/Abbreviation       | Description                                                         |
| ----------------- | ------------------------------------------------------------ |
| **PyPTO**         | PyPTO is CANN's high-performance programming framework that adopts the PTO programming paradigm, designed to simplify the operator development process while retaining high-performance computing capabilities. |
| **PTO**           | PTO (Parallel Tensor/Tile Operation) is a tensor-based programming paradigm. Its core idea is to use tensor as the basic data representation and describe and assemble the complete computation process (or compute graph) through a series of basic tensor operations. |
| **Operation**     | The basic unit in PyPTO that describes elementary operations in a compute graph. Each Operation defines a specific computation logic, capable of processing input tensors and generating output tensors. Complex computation logic can be implemented by combining different Operations. |
| **Compute Graph**        | The complete compilation process from abstract computation description to hardware execution in a PyPTO program.            |
| **Tensor Graph**  | Tensor Graph consists of tensor and Operation nodes, used to describe user-defined computation processes. This graph does not involve low-level semantics such as tile expansion and memory hierarchy, serving only as a high-level expression of computation logic. Optimizations based on Tensor Graph focus primarily on hardware-independent general graph optimization techniques, such as redundant node elimination and constant folding. |
| **Tile Graph**    | Tile Graph consists of Tile and TileOp. Tensor Graph is expanded based on TileShape, decomposing Tensor into Tile and Operation into TileOp. Tile Graph automatically derives the storage location of Tiles based on TileOp information and the memory hierarchy of the target hardware, and inserts memory transfer nodes when necessary to ensure correct data transmission between different memory levels. |
| **Block Graph**   | Block Graph divides Tile Graph into multiple subgraphs, allowing each subgraph to be scheduled and run on a single AI Core. Block Graph is used for hardware-related optimizations, including instruction scheduling, on-chip memory allocation, and synchronization operation insertion, thereby improving hardware execution efficiency. |
| **Execute Graph** | Execute Graph is the final product of the compilation process, integrating all optimization results and precisely describing the dependencies between Block Graphs for device scheduler execution. |
| **Swimlane Diagram**        | The swimlane diagram is used to visually display the actual scheduling and execution process of the compute graph. Through the IDE's visual interface, developers can observe data flow paths, dependencies between operations, and potential performance bottlenecks, enabling more efficient analysis and optimization of operator execution performance. |
| **TileShape**     | A parameter in PyPTO used to define the tiling shape of tensors, determining the parallel granularity and data partitioning mode of operations on hardware. By properly configuring TileShape, memory usage and computation efficiency can be optimized, allowing the computation process to better adapt to hardware characteristics. |
| **Pass**          | A stage in PyPTO for compiling and optimizing the compute graph to improve execution efficiency and hardware utilization. Each pass can perform specific optimization operations on the compute graph, such as graph simplification, operator fusion, and scheduling optimization. |
| **Graph Stitching**          | The process of merging multiple logically independent Operations in a compute graph into a single logical subgraph, which ultimately generates a physical computation kernel. It is primarily divided into depth-wise graph stitching and breadth-wise graph stitching.<br> |
| **Isomorphic Subgraph**      | A local fragment in a compute graph where the topological structure and operator types are completely identical.<br> |
| **Isomorphic Subgraph Group**    | The set formed by fragments that are isomorphic subgraphs of each other is called an isomorphic subgraph group. During the breadth-wise graph stitching pass, a unique feature identifier, namely hashorder, is generated for each isomorphic subgraph group.<br> |
| **stitch**        | Breaks the boundaries of multiple loops and stitches multiple leaf function execution tasks without dependencies into one large task for unified dispatch, reducing synchronization overhead and improving scheduling performance. |
