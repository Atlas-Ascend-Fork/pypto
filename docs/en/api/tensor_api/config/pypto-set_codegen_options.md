## Description

Sets the CodeGen options.

## Prototype

```python
set_codegen_options(*,
                    support_dynamic_aligned: bool = None,
                    enable_pmu_trace: bool = None)
```

## Parameters

| Parameter                     | Input/Output| Description                                                                |
|-----------------------------|-----------|----------------------------------------------------------------------|
| support_dynamic_aligned     | Input     | Meaning: Whether dynamic shapes are supported.<br> Description:<br> If the value is True, the device-side binary generated by the operator supports the dynamic shape alignment scenario.<br> If the value is False, the device-side binary generated by the operator only supports the dynamic shape non-alignment scenario.<br> The option effect will be optimized through the pass derivation mechanism. You are advised to exercise caution when using this option.<br> Type: bool<br> Value range: {True, False}<br> Default value: False (If the operator supports dynamic shapes and the last axis of the shape is aligned, you can enable this option to check whether there are performance benefits.)<br> Affected Pass scope: None. This parameter only affects the device-side target code generated by the CodeGen module.|
| enable_pmu_trace            | Input     | Meaning: Whether to enable PMU Trace.<br> Description:<br> If the value is True, CodeGen inserts `bisheng::cce::mark_stamp` at the beginning and end of the CCE code corresponding to each leaf function and allocates a PMU ID to each mark for locating the corresponding kernel in the in-core pipeline. At runtime, `msprof --instr-profiling=on` must be used for instruction-level collection.<br> If the value is False, PMU marks are not inserted.<br> Type: bool<br> Value range: {True, False}<br> Default value: False<br> Affected Pass scope: None. This parameter only affects the device-side target code generated by the CodeGen module.|

<!-- npu="x90,9030,9050" id15 -->
| Kirin-specific Parameter Name                     | Input/Output| Description                                                                |
|-----------------------------|-----------|----------------------------------------------------------------------|
| soc_version                 | Input     | Meaning: Version of the target SoC (soc_version).<br> Description:<br> The target SoC version used for kernel compilation and running. It corresponds to the name of the CANN platform_config .ini file. One SoC version corresponds to one .ini configuration file.<br> If the value is an empty string (default), the framework obtains the SoC version of the mounted NPU hardware in the current cloud environment through the runtime API (rtGetSocVersion). If no hardware is mounted, you can use this parameter to explicitly specify the target SoC version.<br> Type: str<br> Value range: {Kirin9030, KirinX90, Kirin9050}<br> Default value: "" (empty string)<br> Affected Pass scope: Impacted. The SoC version determines the core architecture (NPUArch). The Passes go through different branches based on the SoC version (for example, IsLiteNPU distinguishes Kirin 9030, Kirin X90, and Kirin 9050). Passes such as auto_cast, assign_memory_type, and iso_partitioner are involved. In addition, the platform architecture of the device-side code generated by CodeGen is affected.|
<!-- end id15 -->

## Return Value

void: The Set method does not return any value. The setting takes effect immediately after the operation is successful.
