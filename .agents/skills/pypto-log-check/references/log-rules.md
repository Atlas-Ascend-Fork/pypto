# PyPTO 日志规范检查规则

## 扫描范围

只评测下列目录中、下列扩展名的源码；`LLT` 目录仅内部调试，不评测。

| 配置项 | 值 |
|--------|----|
| 扫描目录 | `framework/include`, `framework/src`, `python/pypto`, `python/pypto_pro`, `python/src` |
| 代码扩展名 | `.c`, `.h`, `.cpp`, `.hpp`, `.cc`, `.hh`, `.cxx`, `.hxx`, `.py` |

## 严重级

| 顺序 | 级别 | 含义 | 补充说明 | 典型问题 |
|------|------|------|----------|----------|
| 0 | 致命 | 会误导排障方向或造成安全事故 | 如真实敏感值泄露、内部敏感词、严重级别错配导致故障被忽略 | 敏感信息泄露、内部敏感词、ERROR 错配成 INFO |
| 1 | 严重 | 会让人读错意思或搜不到 | 如拼写错误、引起歧义的语法错误、出错日志缺关键信息 | 拼写错误、歧义语法错误、错误描述缺失 |
| 2 | 中等 | 能读懂但不规范 | 如不致歧义的语法错误、绕过统一日志接口、缺度量单位 | 语法错误、绕过日志接口、缺度量单位 |
| 3 | 提示 | 轻微瑕疵 | 如中文残留、非通用缩写、冗余日志 | 中文残留、未知缩写、冗余日志 |

## 规则

所有规则均在本次请求的被检文件范围内评估。

| # | 规则 | 说明 |
|---|------|------|
| 1 | 禁止中文 | 日志统一采用英文输出，避免中英文混杂，必须使用业内通用的英文术语 |
| 2 | 拼写错误 | 日志内容不允许英文单词拼写错误 |
| 3 | 语法错误 | 日志内容不允许语法错误 |
| 4 | 级别错配 | INFO 级别日志中不允许出现 error、fail、Warning、Debug 等明确表示错误或其他级别的词汇；普通否定描述不属于级别词 |
| 5 | 敏感信息 | 密码等敏感信息不能以明文形式记录在日志文件中 |
| 6 | 未知缩写 | 不允许出现公司、部门、项目以及非国际或行业公认的英文缩写 |
| 7 | 禁止自定义打印 | 业务代码禁止自己打印或调用系统打印，必须使用统一日志接口 |
| 8 | 缺少度量单位 | 日志内容中涉及度量信息需标识相应的度量单位 |
| 9 | 错误描述不完整 | 出错或业务失败处，日志必须包含错误描述；变量越限要给出当前值与正确范围，配置错误要给出错误配置项或值与期望值 |
| 10 | 冗余日志 | 流程不可在不同地方输出相同的日志信息 |
| 11 | 魔鬼数字 | 日志内容中不允许出现魔鬼数字，有业务含义的数值须解释为可读字符串 |
| 12 | 内部敏感词 | 日志不得包含内部敏感词，匹配时忽略大小写与空格；当前词表：`Inner Error` |
| 13 | 日志长度或换行违规 | 单条日志内容不得超过 1024 字节，且日志内容中间不得出现换行符 |
| 14 | 非业务错误滥用ERROR | 不影响业务流程的模块内部错误最多使用 WARNING，不得使用 ERROR 污染根因分析 |
| 15 | 算子日志级别与场景不匹配 | 算子交付件日志须按场景使用 ERROR、WARNING、INFO、DEBUG；中止流程用 ERROR，不中止用 WARNING，关键流程用 INFO，调试信息用 DEBUG |
| 16 | 失败日志缺少错误描述 | ERROR、WARNING 或业务失败日志不得只写 failed、error occurred 等泛化文案，必须说明失败对象、动作或具体错误 |
| 17 | 越限错误信息不完整 | 变量或参数越限时，日志必须同时给出当前值和正确取值范围 |
| 18 | 配置错误信息不完整 | 配置错误必须给出错误配置项或配置值，以及期望值或合法范围 |
| 19 | 参数比较信息不完整 | 条件判断或参数比较日志必须记录完整的当前值、期望值和参与比较的关键参数 |
| 20 | ERROR关键定位信息缺失 | ERROR 日志必须包含失败对象、关键参数、返回值或错误码、失败原因等足以支撑定位的信息 |
| 21 | ERROR文件信息缺失 | 文件类 ERROR 必须输出文件名和路径，不能只报告打开、读取或写入失败 |
| 22 | 可恢复错误未标注可忽略 | 内部接口错误经上层重试可自愈时，上层 ERROR 日志必须包含 `error log can be ignored` 标注 |
| 23 | 调用链根因点或影响点缺失 | 多重调用链中，根因处和外层影响流程处都必须有日志，不能只在中间层或外层打印泛化错误 |
| 24 | INFO流程不可还原 | 关键流程应通过 INFO 日志还原；正常主干不能只有零散日志或必须依赖 DEBUG 才能理解 |
| 25 | 异常路径缺少日志 | 异常抛出、错误返回、任务中止或失败状态设置等明确异常路径必须有可定位日志 |
| 26 | 相同日志文案重复 | 同一业务流程或相同调用语义不得在多个位置重复输出相同日志，避免无法区分真实出处 |
| 27 | 循环体内打印高频日志 | 正常循环体内不得打印 INFO 及以上日志；异常点应合并或限频，避免每次迭代输出 |
| 28 | 重试循环重复打印底层错误 | 上层重试不得在每次尝试中无控制地重复打印同一底层错误；应限制次数、合并日志或在最终失败处统一输出 |
| 29 | DEBUG/INFO低价值日志 | DEBUG/INFO 日志必须包含状态变化、关键参数、执行结果或定位价值，不得持续输出固定、无上下文或无业务含义的文案 |
| 30 | 日志格式化参数不匹配 | 日志格式字符串中的 `%s/%d/%p` 或 `{}` 等占位符必须与参数数量、类型和顺序一致，不得造成截断、乱码或未定义行为 |

## 全局判定尺度

- 只报会影响他人阅读、搜索、理解，或误导排障，或造成安全风险的问题。
- 放过程序员约定俗成且意思明确的表达、通用编程缩写，以及无业务歧义的普通计数、端口和大小。
- 不报纯风格与优化建议，如同义词替换、更地道措辞、大小写风格和句子长短；中文或全角标点按“禁止中文”处理。
- 宁缺毋滥：宁可少报几条准确问题，也不要增加误报。

## 规则补充尺度

多个判定要点使用 `<br>` 分隔。规则名必须与上方规则表一致。

| 规则 | 补充判定尺度 |
|------|--------------|
| 禁止中文 | 只检查运行时实际输出的字符串；注释、文档示例和代码标识符不报。文案里的汉字、中文标点和全角字符都算问题，并给出具体英文文案或半角标点替换建议。 |
| 拼写错误 | 只检查实际输出文案中的普通英文单词。文案引用项目真实存在的函数、方法、宏、类型或协议字段时，保留源码中的原始拼写，不按自然语言词典强制纠正。上下文不足以确认是普通单词时不报。 |
| 语法错误 | 只报确凿的语法错误，如主谓不一致、缺助动词、动词形式错误、介词误用、字符串拼接漏空格或句子结构残缺到读不懂。<br>不报措辞与风格类改写，判断标准是错误而不是不够地道。 |
| 级别错配 | 仅当宏和包装调用完整展开后的实际日志级别为 INFO，且输出文案含 error、fail/failed/failure、warning/warn、debug、fatal 等明确跨级别词时才报，例如最终为 LOGI 的调用输出 xxx failed；任一条件无法确认都不报。<br>`Can not get...`、`cannot...`、`unable to...`、`not found` 等普通否定、未获取或降级描述本身不属于级别词，不能仅凭其语义推断为级别错配；文案若存在 `notget` 等缺空格或拼写问题，按拼写错误或语法错误单独判断。<br>WARNING 级说 failed、DEBUG 级提 exception 属正常，不报。宏定义链最终落到 `IDE_LOGE` 时按 ERROR 级判断，不能因外层包装名称像 INFO 而报告级别错配。 |
| 敏感信息 | 必须会打印真实敏感值才算，例如 password=%s 搭配密码变量，或写死的密钥、token、银行卡号。<br>仅出现 password、token、key、secret 单词而未打印真实值时不报。 |
| 未知缩写 | 只报公司、部门、项目代号等外部人员完全无法查到含义的缩写。<br>放过领域内可查的技术缩写、算子名、算法名和张量维度名。 |
| 禁止自定义打印 | 只在业务调用点直接使用 printf、fprintf、cout、cerr、Python print 或 JS console.log 承担日志、状态或调试输出时报告。<br>UT 源码中的 cout、printf 属于测试诊断输出，不报告本规则；其输出文案仍继续检查中文、拼写、敏感信息等其它规则。<br>项目自定义日志宏/包装函数的定义及调用视为统一入口，不因其底层最终调用系统打印而报告本规则。<br>C/C++ 核心代码通常判中等；Python、JS、示例和 demo 通常判提示。<br>输出若已报告中文、拼写等更具体问题，不再叠加本规则。公共 CLI 或管道协议输出不是日志或调试状态时放过。 |
| 缺少度量单位 | 只报会造成量级误解的耗时、内存、带宽等度量值。<br>放过计数、下标、维度、层数和表格表头等无单位可言的数值。 |
| 错误描述不完整 | 只报告变量越限缺当前值或正确范围，以及配置错误缺错误配置项、值或期望值。<br>一般操作失败、系统调用失败或资源创建失败，只要说明失败对象或动作，就不强制补当前值、期望值、错误码和原因。 |
| 冗余日志 | 只报同一业务流程里重复输出、会让人分不清执行到哪一步的日志。<br>放过分隔线、进度标记、循环内按批次打印及不同模块各自记录同类信息。 |
| 魔鬼数字 | 只报输出文案里写死且不查表无法理解的状态码或枚举值。<br>%d、%u、{} 等格式占位符以及 retcode、status 变量值不是写死数字。<br>放过阈值、尺寸、批次、通道数和对齐位数等有明确物理含义的数值。 |
| 内部敏感词 | 只检查运行时实际输出的字符串文案；宏名、函数名、变量名和代码标识符不属于日志文案。<br>只有实际输出文本包含黑名单词时才报。 |
| 日志长度或换行违规 | 只在源码能确定静态文案或拼接结果超过 1024 字节，或明确把换行符写入单条日志时报告；无法确定动态变量最终长度时不报。 |
| 非业务错误滥用ERROR | 只有能够从源码上下文确认该错误不影响业务流程、会被上层忽略或可继续运行时才报告；无法确认业务影响时不报。 |
| 算子日志级别与场景不匹配 | 根据分支语义判断：流程中止或交付失败应使用 ERROR，不中止但需关注应使用 WARNING，关键正常流程使用 INFO，调试细节使用 DEBUG；无法确认场景时不报。 |
| 失败日志缺少错误描述 | 只报告明确失败、异常或业务失败路径中没有失败对象、动作或具体原因的日志；仅写 `failed`、`error`、`exception` 等泛化词不算有效描述。 |
| 越限错误信息不完整 | 只在日志明确表达越界、超限、范围非法或约束不满足时检查；必须同时有当前值和合法范围，格式化占位符及变量名本身不算实际值。 |
| 配置错误信息不完整 | 只在源码明确判定配置非法时检查；错误配置项/值与期望值/范围至少应成对出现，不能要求普通配置加载失败补充无关信息。 |
| 参数比较信息不完整 | 只检查日志所在判断语句实际参与比较、且对定位有意义的参数；不要求打印无关局部变量。 |
| ERROR关键定位信息缺失 | 只报告确实无法确定失败对象、关键输入、返回值/错误码或原因的 ERROR；若完整信息通过同一调用链可确认会被输出，应放过。 |
| ERROR文件信息缺失 | 仅针对文件、目录、配置文件、模型文件等文件类操作；必须能从源码确认文件名或路径会进入日志输出。 |
| 可恢复错误未标注可忽略 | 只有源码同时存在底层错误、上层重试/降级并可继续运行的调用模式时才报告；普通 ERROR 不要求添加该标注。 |
| 调用链根因点或影响点缺失 | 只在源码能确认调用关系和错误传播方向时报告；不能仅凭函数名猜测根因或外层影响点。 |
| INFO流程不可还原 | 只检查关键分支、阶段切换和结果状态均可从源码确认的流程；不要求为每个普通语句增加 INFO。 |
| 异常路径缺少日志 | 只报告明确的异常、失败返回、终止流程或失败状态设置路径；正常早返回、可选分支和测试断言不适用。 |
| 相同日志文案重复 | 在当前请求的被检文件范围内按文案和调用语义判断重复，放过不同模块独立记录、批次进度和必要的分层上下文。 |
| 循环体内打印高频日志 | 只报告正常循环体内的 INFO/WARNING/ERROR；循环中的异常日志、明确限频日志和 DEBUG 诊断日志按上下文判断。 |
| 重试循环重复打印底层错误 | 只报告源码存在循环/递归重试且每次都直接打印同一底层错误的情况；有明确最大次数、限频、聚合或最终失败日志时放过。 |
| DEBUG/INFO低价值日志 | 只报告文案和上下文均无法提供状态、对象、参数、结果或定位价值的日志；不因句子简短、风格普通或缺少主语而报告。 |
| 日志格式化参数不匹配 | 仅在格式字符串、宏展开和实参可从源码确定时报告；无法确认包装宏最终格式或参数类型时不报。 |
