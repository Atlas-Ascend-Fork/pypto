# PyPTO Pro Review and Fix

主 agent 在用户调用本技能，或开发任务已约定完成后审核修复时执行。本技能授权修复本任务范围内
已确认的问题；规则与独立角色执行复用 [pypto-pro-code-review](../pypto-pro-code-review/SKILL.md)。
单独调用检视技能不授权修复。

## 输入、角色与状态

保留用户需求、已确认方案、兼容性及范围边界。默认同时检查功能与规范；仅规范请求传递 `rules` 模式。
pto-isa 专项须用户明确开启。主 agent 修复代码，reviewer/verifier 不修改被检源码或发布意见。
改变已确认方案前仍需用户确认；已有对应授权不重复询问。

在任务专属临时目录保存状态、原始 diff/必要文件版本、各轮报告及验证日志；记录目录绝对路径以便恢复。
先读取 [状态脚本协议](references/state-protocol.md)，用 `scripts/review_state.py` 管理本次运行。
脚本是轮次、阈值及状态转移的执行入口；不手改 JSON 计数，不在会话压缩后重新 `init`。

主 agent 一次准备客观材料；每轮按检视技能创建独立功能/规则 reviewer，再创建独立 verifier。
仅规范模式省略功能 reviewer。一组角色算一轮；角色只执行分配任务，不递归启动工作流。

## 执行循环

1. **初始化或恢复**：固定原始任务基点及方案，记录检视范围和已有验证。
   PR 使用固定 SHA，本地改动保存原始 diff、相关新增源码及读取的文件版本。
   `show` 检查已有记录；未开始的任务才 `init`，恢复不清零。
2. **开始一轮**：先固定本轮源码版本及输入产物，再 `begin`，之后才启动第一个 reviewer。
   使用脚本返回的 `next_mode`/本轮 `mode` 决定范围。新增角色不另计一轮；失败也不能撤销本轮次数。
3. **检视和复核**：按单轮技能完成客观材料交接、按需读取、分工检视及证据定位复核。
   首次发现不读已有评论；复审传递上轮台账，区分本轮引入、此前漏检和修复后复发。
   可取得的证据继续查清，无法完成的记录缺口。
4. **记录结果**：主 agent 合并 verifier 确认的根因，带上完整历史问题台账和版本匹配的验证结果执行 `finish`。
   所有旧 ID 都保留，关闭或否定须有证据，不能通过省略问题使数量下降。
5. **按状态行动**：`fix` 修复确认问题及已定位的验证失败；`assess` 先反思方案；
   `passed` 交付；`needs_human`、`stopped` 或 `awaiting_approval` 返回明确结果。
   修复后的必要构建、Host/NPU 验证使用项目指令，核实源码与导入产物一致，然后固定新版本进入下一轮。

### 审核范围与收敛

- 当前方案先完成 **2 轮完整审核**：读取原始基点到当前版本的全部 diff，放回完整函数、类型、模块和调用链。
- 之后若最近两轮未解决问题数下降、Blocker/Major 各自数量未增加且无已关闭问题复发，进入增量审核。
  增量审核检查上轮以来的改动、全部未解决问题及受影响上下游；无可靠基线时仍做完整审核。
  收敛条件不再满足时恢复完整审核，原始基点不改变。
- **零问题可提前结束**。通过还要求所有角色和覆盖完成、无未决候选、必要验证通过，且均对应当前版本。
- 主 agent 按根因批量修复全部确认问题，包括 Minor 规范违规；证据不足的候选先核实。

### 方案反思及重置

`N` 为两个 reviewer 经复核、按根因去重后的未解决确认问题数。脚本在下列情况返回 `assess`：

- 第二轮完整审核后 `N >= 5`，且比第一轮下降不足 30%。
- 声称修复的 Blocker/Major 仍存在、已关闭的严重问题复发，或修复引入新的 Blocker/Major。
- 同一方案连续两个轮间比较均未下降，即最近三轮 `N` 非递减。

主 agent 对照证据区分方案缺陷、修复遗漏、此前漏检和误报，用 `assess` 记录结论与依据：

- `sound`：当前方案成立，并给出下一批可执行修复。没有修复方向则返回人工处理。
- `flawed`：方案存在问题。首次连续确认须提出最小修订，返回 `awaiting_approval`。
  用户明确批准（或已有该修订的明确授权）后 `approve`；真正落实修订后 `revise`。
  仅此时清零当前方案完整审核次数，累计次数、原始基点和问题台账保留。
- `unknown`：缺少关键证据或决策，返回人工处理。

**连续两次反思确认方案存在问题，立即退出自动循环**，不再实施下一套方案。
连续性只被后续基于实际审核证据的 `sound` 反思打断；普通审核、修复、用户批准新方案和阶段重置均不清零。
同一次反思只记录一次。

## 结束与人工交接

累计 **最多 5 轮**，包括方案调整前后的所有尝试。第五轮通过可以交付，否则不再自动修复或发起第六轮。
关键证据、独立角色或必要验证无法在授权范围内完成时，保留已完成工作并返回人工处理。
用户要求停止时记录 `stop`，保留工作区，不自动回退改动。

返回：通过 / 等待方案确认 / 需要人工介入 / 用户终止。报告应包含当前版本、修复结果、剩余问题、
角色与覆盖完成情况、三项计数、验证结果、产物路径及具体待决事项。
需要改变确认方案时说明问题、影响和最小修订，指出项目指令的确认边界。
同一任务恢复沿用原状态；人工明确批准新的尝试后才创建关联的新记录并保留原运行路径及批准依据。
本技能不自动 commit、push、发布评论或回复远端线程。
