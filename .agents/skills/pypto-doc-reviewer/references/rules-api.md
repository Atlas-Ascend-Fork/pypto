# API 文档写作规范

适用范围：`docs/zh/api/` 下所有文档，分两类骨架：**API 文档**（接口说明，如 `tensor_api/operation/`、`pro_api/`）与**数据结构类文档**（枚举/类定义，如 `tensor_api/datatype/`）。

规则编号范围：API 文档 `API-01~30`，数据结构类文档 `DS-01~04`。

本文件分两部分：**规则**（按文档章节组织，写作时遵守）与**检查方法**（排查验证手段）。

## 规则

### 章节结构

#### API 文档（API-01~04）

固定 8 个二级标题，顺序不可颠倒（参考 `docs/zh/api/tensor_api/operation/pypto-bitwise_and.md`）：

```
# <接口名>
## 产品支持情况
## 功能说明
## 函数原型
## 参数说明
## 返回值说明
## 约束说明
## 调用示例
```

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| API-01 | API 文档 8 个章节齐全且顺序固定，不得删减章节或改名（"参数说明"不可写成"参数"）；可适当扩展新增章节（如"使用建议"），但不得破坏既有章节顺序 | HIGH |
| API-02 | "产品支持情况"必须是第一个二级标题（两类文档通用） | HIGH |
| API-03 | 一级标题格式：tensor_api 为 `# pypto.<op名>`（下划线转义为 `\_`，如 `# pypto.bitwise\_and`）；pro_api 为 `# pypto_pro.<模块>.<函数>`（如 `# pypto_pro.language.trap`）。标题须与函数原型中的完整调用名一致 | HIGH |
| API-04 | 当接口无参数/无返回值/无约束等导致对应章节（如"参数说明"）无实际内容时，**章节节点必须保留**：标题不得省略或删除，正文内容写"无"（参考 `docs/zh/api/pro_api/Utils-API/debugging/trap.md`；两类文档通用） | HIGH |

#### 数据结构类文档（DS-01~04）

固定包含以下部分（参考 `docs/zh/api/tensor_api/datatype/TileOpFormat.md`）：

```
# <数据接口名>
## 产品支持情况
## 功能说明
## 原型定义
```

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| DS-01 | 固定包含：数据接口名（一级标题，与代码中类/枚举定义名一致，如 `# TileOpFormat`）、产品支持情况、功能说明、原型定义，固定部分不得删减 | HIGH |
| DS-02 | 原型定义中直接以注释形式解释每个类型或枚举值的含义（如 `TILEOP_ND = ...  # N维Tensor，支持标准的多维数组操作`） | HIGH |
| DS-03 | 参数过于复杂时，可增加"参数说明"章节，使用表格解释（表格格式遵循 API-16） | MEDIUM |
| DS-04 | 可按需扩展其他章节（如约束说明、使用示例、使用建议），但固定部分顺序不得改变 | MEDIUM |

### 产品支持情况（API-05~06）

以下规则对两类文档均适用。

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| API-05 | 须包含 rules-product.md 中 Ascend/Atlas **三款必列型号**（不得缺少任一）；Kirin 型号的列入规则见 PRD-01（行格式与取值见 API-06） | HIGH |
| API-06 | "产品支持情况"中每个型号**各占一行**，分别用对应芯片的 npu 标签包裹，以支持按芯片过滤发布；取值不得留空、仅可填"支持"或"不支持"，无"部分支持"选项（特性级差异按 PRD-10 在"约束说明"章节展开）（标签语法与配对见 PRD-03~07，标签值与产品名对应关系见 PRD-06） | HIGH |

### 功能说明（API-07~12）

以下规则对 API 文档与数据结构类文档的"功能说明"章节均适用。

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| API-07 | 介绍接口功能与用途，须明确使用场景（何时/何种需求下使用该接口） | HIGH |
| API-08 | 强调"做什么"而非"怎么做"：描述接口提供的能力与效果，不描述 API 内部实现原理、编译机制等技术细节（特殊情况除外，如确需说明机制才能正确使用的接口） | HIGH |
| API-09 | 与其他 API 配合使用时，须描述配合关系（如"调用本接口前，应通过 set_vec_tile_shapes 设置 TileShape"） | MEDIUM |
| API-10 | 与其他 API 功能类似时，须描述两者区别（功能差异、适用场景差异），帮助用户选型 | MEDIUM |
| API-11 | 计算类接口可酌情增加计算公式：使用 `$$...$$` 块，变量下标用 LaTeX 语法（如 `\text{res}_i`）；**公式中的变量名必须与函数原型中的参数名一致**（如原型参数为 `input`、`other`，公式中用 `\text{input}_i`、`\text{other}_i`） | MEDIUM |
| API-12 | 复杂接口可酌情增加清晰图示（如处理流程图）；图片存放与命名遵循开源文档写作规范（IMG-01~02） | LOW |

### 函数原型（API-13~15）

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| API-13 | 使用 ` ```python ` 代码块声明，含类型标注；原型统一**不加 `def` 关键字和末尾冒号**，直接写 `函数名(参数) -> 返回类型`（如 `bitwise_and(input: Tensor, other: Union[Tensor, int]) -> Tensor`） | HIGH |
| API-14 | 原型必须与代码实现一致：函数名、参数名、参数顺序、类型、返回值。若 PR 修改了 `.py` 签名，对应文档必须同步更新，不得遗留旧原型 | CRITICAL |
| API-15 | 存在多个重载/变体接口时，须分别列出原型并明确标注适用场景 | MEDIUM |

### 参数说明（API-16~21）

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| API-16 | 使用表格，列为：`参数名`、`输入/输出`、`说明`；每个参数一行，与原型参数一一对应，不得遗漏或多余 | HIGH |
| API-17 | "说明"列包含但不限于：参数含义、单位、取值、默认值、约束信息（Shape 维度限制如"仅支持1-4维"、不支持空 Tensor、Shape Size 上限、广播行为等）——如不涉及，可删减对应内容 | HIGH |
| API-18 | 当某个参数在不同型号间存在差异时，建议将差异内容归入"约束说明"章节，并在参数说明中引导用户跳转（如 `详细请参见[约束说明](#约束说明)`）。原因：① 表格中不建议使用芯片标签；② 便于用户快速了解产品差异；③ 便于后续文档定制化扩展和版本迭代维护 | MEDIUM |
| API-19 | 输入/输出列只填"输入"或"输出" | MEDIUM |
| API-20 | 数值类参数须明确：单位、取值范围、默认值、支持的数据类型；若函数原型中已比较明确（如类型标注完整的数值参数），可不强制 | MEDIUM |
| API-21 | 数据结构类参数（枚举/类/结构体，如 CastMode、TileOpFormat）：其定义与成员含义须**单独维护一份数据结构类文档**（如 `tensor_api/datatype/`、`pro_api/SIMD-API/basic_data_structures/` 下，写法见 DS-01~04）；API 参考的参数说明中**不得重复罗列数据结构的成员定义**，只须描述参数用途并附链接参见对应数据结构文档——避免同一数据结构被多个 API 使用时产生多个描述源头 | HIGH |

### 返回值说明（API-22）

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| API-22 | 说明返回值类型与语义（如"返回输出Tensor，数据类型和input、other相同，Shape为input和other广播后大小"） | HIGH |

### 约束说明（API-23~25）

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| API-23 | 型号间功能差异（支持的数据类型列表、格式限制等）统一放本章节，用 npu 芯片标签区分（见 rules-product.md），不散落在参数说明中 | HIGH |
| API-24 | 章节定位：约束说明建议体现该接口的**接口级使用约束**或**较通用的约束**；参数级约束（非型号差异）应尽量在参数说明中就近体现，避免信息过于零散（型号间差异仍按 API-23 归入本章节） | MEDIUM |
| API-25 | 约束数量控制：过多的约束影响用户体验；新增约束前应优先评估软件是否有优化空间，避免增加不合理的约束 | MEDIUM |

### 调用示例（API-26~30）

| 编号 | 规则 | 严重级别 |
|------|------|---------|
| API-26 | 示例代码可独立运行：import 完整、无未定义变量/函数、API 参数在合法范围内 | HIGH |
| API-27 | 示例代码不使用交互式会话格式（`>>>` REPL 风格），统一使用普通脚本形式 | MEDIUM |
| API-28 | 涉及 TileShape 前置设置的接口（vec 类操作），示例须先调用 `set_vec_tile_shapes` 并说明设置依据 | MEDIUM |
| API-29 | 结果示例按接口类型区分：**vector 计算 API** 为方便用户理解计算逻辑，建议给出结果示例（"结果示例如下"代码块）；**cube 计算 API** 由于计算逻辑复杂，可不提供结果示例 | LOW |
| API-30 | 块级代码示例使用三反引号围栏代码块（如 ` ```python `），并声明语言类型（python、bash、json 等），上下空一行 | MEDIUM |

> 全文通用的表达约定（标识符引用风格、锚点与链接规范、pro 接口命名、数据类型写法、功能开关用词）见 [rules-terms.md](rules-terms.md)「表达约定」。

## 检查方法

### 原型与代码一致性核对（API-14）

对 PR 中变更的 API 文档，在 `python/` 下定位对应函数定义（grep 函数名），逐字段比对原型。

### 说明内容与代码核对（API-14、API-17）

参数说明、约束说明中的事实性内容须与实现代码一致。在 `framework/src/interface/` 下 grep 算子名（如 `grep -rn "Digamma" framework/src/interface/`）定位算子实现，核对：

- 数据类型列表 ↔ 实现中 `supportedTypes`（漏写、多写均算不一致，漏写为 HIGH——会让用户误认为不支持）
- Shape 维度约束 ↔ `CheckTensorDimRange`
- 格式约束 ↔ `CheckTensorFormat`
- 临时内存等数值约束 ↔ 实现 tmp 缓冲系数（换算惯例：文档系数 = 代码系数 + 输入 + 输出，如 erf 代码 `NUM_VALUE_3` → 文档 5）

### 同类既有文档惯例比对（API-01）

与结构参照文档 `pypto-bitwise_and.md` 及同族算子文档（如同为数学计算的 `pypto-erf.md`）比对章节结构、参数表写法、约束表述、示例风格。只报偏离全仓惯例的项；与既有惯例一致的表述不重复报告。
