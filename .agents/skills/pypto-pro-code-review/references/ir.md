## 模块专属规则

### PRO-IR-001：保持基础 IR 的通用性

- **适用条件**：新增功能涉及基础 IR expr、stmt、type 的新增或修改。
- **检查内容**：IR 是描述程序结构的通用数据结构，非必要不新增或修改基础节点和类型。
  优先判断能否用现有 IR 及新增 call op 表达特定功能，不能因新增一个功能就直接修改基础 IR。
  结合公共规则 `PRO-DATA-001` 检查结构复用与必要性。
- **报告证据**：现有节点或 call op 可表达该功能的具体方式，或新增基础结构缺乏通用性、必要性的依据。
  若现有表达能力确实不足，应评估其通用语义，不能把此规则解读为绝对禁止扩展 IR。
- **用户依据**：通用 5.4；IR 1。

### PRO-IR-002：类型继承与比较的前置条件

- **适用条件**：新增 IR 类型子类，或修改类型比较、类型转换与派发。
- **检查内容**：分别核对基类/基类、子类/子类、基类/子类及反向比较；区分完整类型相等与
  仅比较基类属性的调用契约。访问子类字段前确认两侧转换成功，写明保证来自当前分支还是
  上游的 kind/TypeName 检查；子类专属检查先于继承字段比较，避免隐式依赖掩盖比较语义。
  同时核对新增字段在相等与哈希中的处理是否一致。
  精确 kind 判断改成基类匹配时，比较实际纳入的类型集合及后续校验，不能只因条件写法变化
  判为语义回退。注册宏被删除时，追踪其手写特化或派发替代，确认基类与子类是否仍被覆盖。
  复合条件中各类型判断的修改必要性及风格统一边界，按公共规则 `PRO-SIMPLE-001` 分别核对。
- **报告证据**：具体类型对、比较入口、转换和保护路径；断言或返回 false 应符合该入口已有契约。
- **反例**：已由同一入口的类型判别保证转换成功时，不能虚报空指针故障，也不要求所有转换
  机械增加空检查。局部表达需调整时，明确其属于可读性或既定实现规范，不混作运行时缺陷。
- **用户依据**：commit `0453be178a5b0a3d69acfe2a2e1aafd59921ec9f` 的类型比较检视意见
  （后迁移至 PR 7055，评论 `195148664`、`195148336`、`195148893`）；需结合
  `StructuralEqualImpl::EqualType`、`KindTrait<TileType>` 及 verifier 的入口保护复核。

tuple type 表达多种类别及 `debugInfo` 的约定统一维护在公共规则 `PRO-TUPLE-001` 中。
修改 tuple 构造、传递或比较时同时检查该规则，不在本文件重复定义。
