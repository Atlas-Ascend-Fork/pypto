# JIT / runtime 检视规则

## 适用范围

JIT 模式与二进制模式的目标架构选择、源码组装、编译配置、缓存及 kernel 执行的改动。
本模块负责串联框架流程；代码结构分析、优化和变换功能遵循 [Pass 规则](pass.md)。
涉及构图或生成代码的接口约定时，通过[模块索引](review-checklist.md)
加载 DSL、IR、codegen 等相关模块规则。

## 模块专属规则

### PRO-RUNTIME-001：JIT 与二进制模式复用公共编译流程

- **适用条件**：新增或修改 JIT 模式与二进制模式都需要的编译相关逻辑。
- **检查内容**：将共同逻辑放到两种模式共有的流程中，例如 `_codegen`，避免重复实现两套编译逻辑。
  先追踪两个入口的调用链，确定合适的共享位置；`_codegen` 是示例，不要求所有逻辑都塞入该函数。
- **报告证据**：两种模式中的重复实现、各自调用链，以及能够共同调用该逻辑的位置。
  只属于一种模式的逻辑不属于本条要求合并的共同逻辑。
- **用户依据**：通用 5.5；JIT/runtime 1。

### PRO-RUNTIME-002：源码组装、编译策略与执行入口的职责

- **适用条件**：新增 kernel 特性，改变 caller 源码、编译选项或普通与特殊执行入口。
- **检查内容**：先按 `PRO-MODULE-001` 区分特性对 `kernel.cpp` 与 `call_kernel.cpp` 的影响，
  核对 codegen 是否完成其负责部分的闭环；再沿特性元数据到 caller、编译参数和入口调用追踪：
  - caller 源码的组装由生成函数负责，例如 `_generate_caller_cpp` 及其 helper；编排层不应新增
    入口源码生成策略，再把零散源码片段交给生成函数拼接。
  - 特性所需的 include、宏及 cflag 由编译阶段根据 kernel 特性统一决定，例如
    `_compile_shared_library` 及编译配置 helper；优先复用已有 kernel 元数据载体，
    不在上层重复读取环境、拆解能力位或生成搜索路径后，仅让编译函数追加结果。
  - 普通入口与特殊入口共享实现时，先核实兼容接口能否消除特殊适配，再区分外部 ABI、
    内部调用参数及运行环境提供的值，不能只验证现有改写方案能否传通参数。
    对 block/grid 等值明确其来源、单位和作用域，检查两条路径各自满足共享实现的契约；
    不能直接把普通 launch 的内建值与特殊调度器提供的逻辑值视为等价。
- **报告证据**：策略决定处、参数传递处和最终消费处，以及本可统一负责该逻辑的已有函数。
  区分本次新增的职责分散与历史结构；共享实现的入口适配须指出可避免的跨层实现或具体契约偏差，
  无须以运行时错误证明已确认的职责违规。与 `PRO-MODULE-001` 同根因的问题合并报告。
- **反例**：职责明确的 helper 分解、编排层传递 kernel 特性，或接口明确允许调用方指定的
  外部 include/cflag，不等于策略泄露。以上函数名是当前源码入口，不要求把实现塞进单个大函数，
  也不要求为此建立通用配置框架。
- **用户依据**：通用 2.1–2.2、3.2、5.5；[PR 7036](https://gitcode.com/cann/pypto/pull/7036)
  的补充意见 195226454、195230395、195228653（编译配置、caller 生成及入口契约）。
